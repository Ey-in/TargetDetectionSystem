# 引用与第三方来源登记

> 课程原文：*"禁止直接使用现成代码：所有实验需基于自主设计、编码和调试，禁止直接下载或复制网上
> 完整代码运行。若参考开源代码，需在实验报告中明确标注来源，并说明对代码的修改、优化或创新点。"*
>
> 本文件就是这条要求的落地台账。**登记本身不是负担，它恰恰是我们证明合规的方式。**

---

## 一、规则

1. **禁止整体拷贝现成项目。** 不允许找一个"YOLO + Web 界面"的完整仓库改改就交。
2. **允许把开源库作为依赖使用**（如 `pip install ultralytics`），但必须在下表登记。
3. **凡引入或改写第三方代码片段** —— 无论是来自开源项目、博客、Stack Overflow 还是
   AI 对话 —— 都要登记来源，并写明**我们改了什么**。
4. **同一个 PR 内完成登记。** 评审时没登记的一律要求删除或补登记。
5. **后处理自研。** NMS、置信度阈值、类别过滤用纯 NumPy 自己实现，不调用库里的同名函数。
   这是本项目里"自主设计编码"最实在的体现。

登记范围是"用了别人的东西"，不是"用了别人的工具"。用 Python 标准库、用 `git`、用 `pytest`
都不需要登记 —— 登记的是**被集成进我们系统、影响系统行为的第三方组件与代码**。

## 四、关于 AGPL-3.0 的注意事项 ⚠️

`ultralytics` 采用 **AGPL-3.0**，其特点需要全组知晓：

1. **约束范围广**：不仅覆盖库代码，**用它训练产出的模型权重同样受 AGPL-3.0 约束**。
2. **网络服务也算分发**：AGPL 的"A"（Affero）就是针对这一点 —— 即使只提供网络服务、
   不分发软件本体，也要求向使用者提供源代码。这正是它强于 GPL 的地方。
3. **对策**：本项目**以 AGPL-3.0 发布**（见 README「许可证」一节），保持许可证一致。
   课程项目不涉及商业分发，采用同许可证即可完全合规。
4. **若将来需要闭源**：可考虑 Apache-2.0 的替代检测模型（如 YOLOX、RT-DETR 系列），
   届时需重新评估。**本课程项目不需要做这个取舍**，此处仅作记录。

> 许可证信息以官方页面为准，本文件记录的是选型时的判断依据。
