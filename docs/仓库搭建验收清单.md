## 四、网络与访问

### 结论：git 操作一律用 SSH

```powershell
git clone git@github.com:Ey-in/TargetDetectionSystem.git
```

**不要照抄网页上显示的 `https://` 地址。**

### 实测情况

| 访问方式 | VPN 关闭 | VPN 开启（TUN/全局模式） |
|---|---|---|
| SSH（`git@github.com:...`） | ✅ 可用 | ✅ 可用 |
| HTTPS（`https://github.com/...`） | ❌ 443 超时，卡 20 秒后失败 | ✅ 可用 |

推荐 SSH 的真正理由**不是"https 不能用"**，而是 **SSH 不依赖 VPN 状态**。
依赖 VPN 的话，哪天 VPN 抽风或忘了开，就会出现"今天能推、明天不能推"这种难排查的问题。

### 兜底方案

| 情况 | 处理 |
|---|---|
| 首次配置 SSH | `ssh-keygen -t ed25519`，把 `~/.ssh/id_ed25519.pub` 贴到 GitHub → Settings → SSH keys |
| 验证是否可用 | `ssh -T git@github.com`，看到 `Hi <你的用户名>!` 即成功 |
| 22 端口被封 | `~/.ssh/config` 加 `Host github.com` / `HostName ssh.github.com` / `Port 443` / `User git` |
| 确实要用 https | 先确认 VPN 已开启；仍失败则配代理 `git config --global http.proxy http://127.0.0.1:7897`（按自己的端口改） |

> 打开 GitHub 网页做操作前，先确认 VPN 在运行。

## 五、为什么现在网页上没有「合并分支」的入口

**因为尚未创建 Pull Request，而 GitHub 上合并分支只能通过 PR 发生** ——
它没有"把两条分支直接合并"的按钮。

当前状态：

```
远端 refs/heads/main                = a71ab28  （仍是初始提交）
远端 refs/heads/chore/repo-bootstrap = 9 个提交（脚手架）
```

分支已经推上去了，但 PR 还没开。这是**刻意设计**的：让脚手架本身走一遍完整的 PR 流程，
顺便把上面第三节列的五项机制一次性激活并验证。

### 怎么开

仓库首页通常会出现黄色横幅 *"... had recent pushes — Compare & pull request"*。
没看到就直接访问：

```
https://github.com/Ey-in/TargetDetectionSystem/pull/new/chore/repo-bootstrap
```

| 项 | 填什么 |
|---|---|
| 标题 | `chore: 搭建仓库协作流程与开发规范` |
| 正文 | 模板会自动注入，**逐条勾选合规声明** |
| 评审人 | 指定一名组员（不能是作者本人） |
| 合并方式 | **Squash and merge** |

> ⚠️ PR 标题必须符合 Conventional Commits：CI 会校验它，
> 因为 Squash 合并后这个标题会成为 main 上的提交信息。

## 六、LICENSE

### 现状

**尚未添加。** 但 `README.md` 的「许可证」一节已经写明本项目以 **AGPL-3.0** 发布 ——
也就是说**目前存在一处自相矛盾**，需要二选一处理。

### 建议：添加

理由三条，第一条最实际：

1. **README 已经这么声明了**，没有 LICENSE 文件前后不一致，答辩被问"到底哪个许可证"会很难看。
2. 公开仓库没有 LICENSE 文件，法律默认是**"保留所有权利"** —— 连同学都不能合法使用你的代码，
   这通常不是本意。
3. 项目依赖 ultralytics（AGPL-3.0，且**该许可证的约束延伸到它训练出的模型权重**），
   本项目声明同一许可证是唯一自洽的做法。

### 怎么加（约 30 秒）

1. 仓库首页 → **Add file** → **Create new file**
2. 文件名填 `LICENSE`
3. 右侧出现 **Choose a license template** → 选 **GNU Affero General Public License v3.0**
4. Commit

> 用官方模板而不是手抄，是为了拿到准确的法律文本。
