> 一条需求从提出到验证，全程使用同一个编号。改动任何一环，都必须回来更新本表。

## 编号规则

| 前缀 | 含义 | 例 |
|---|---|---|
| `FR-xx` | 功能需求 | `FR-01` 图片检测 |
| `NFR-xx` | 非功能需求 | `NFR-01` 单张图片推理耗时 |
| `DR-xx` | 数据需求 | `DR-01` 检测历史记录 |
| `TC-xx` | 测试用例（**必须与 `tests/` 下真实用例一一对应**） | `TC-01` |
| `REQ-Issue` | 提出该需求的 Issue 编号 | `#3` |

## 维护规则

1. **需求变更必须双向同步**：改需求文档 → 同步本矩阵 → 改代码 → 补测试。不允许悄悄改代码。
2. **`TC-xx` 必须真实存在**。文档里写了用例编号，`tests/` 里就必须能找到对应测试；
   评审时会核对，对不上视为造假。
3. **一行的"代码位置"必须能点开看到东西**，写"整个 src/"等于没写。
4. 每完成一个里程碑，配置管理员归档一次本文件快照（配合 tag）。
