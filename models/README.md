# 模型权重目录

> **本目录下的内容不会进入 git**（`.gitignore` 已忽略，仅保留本文件）。

## 为什么不入库

1. 与数据集同理，GitHub 免费 LFS 额度只有 1GB，权重一大就会耗尽；
2. 权重是**训练产物**，不是源码。把它塞进 git 会让历史迅速膨胀，且无法 diff。

## 权重的三种来源

| 来源 | 获取方式 | 用途 |
|---|---|---|
| 官方预训练权重 | ultralytics 首次运行时自动下载，或从官方 release 获取 | 开箱推理；也是我们自己训练的起点 |
| 我们自己训练的权重 | 训练产出，**走 GitHub Release 附件分发**（见下） | 演示与评估用 |
| 临时实验权重 | 不入库也不发布 | `exp/` 分支训练时产生，用完即弃 |

## 自己训练的权重怎么分发

训练完成后，把最终的 `best.pt` 作为 **GitHub Release 的附件**上传：

1. 仓库 → Releases → Draft a new release
2. Tag 用里程碑 tag，例如 `v0.3-模型基线`
3. 在附件区拖入 `best.pt`，说明里写清：训练数据、超参、mAP、训练时长、训练人
4. Publish

组员从 Release 页面下载后放到本目录即可。

> Release 附件不占 LFS 额度，且天然带版本与说明，比丢在群里强得多。

## 训练记录也是工作量证明

训练过程（超参数、数据集版本、耗时、指标曲线）请一并留痕：

- 训练脚本提交到仓库并走 PR
- 超参与结果记进 Release 说明
- 关键调参实验走 `exp/` 分支，PR 中写明"试了什么、结果如何、为什么放弃"

课程要求提交工作量证明，而训练调参往往占了整个项目最多的时间 ——
**这段过程如果不留痕，等于白干。**
